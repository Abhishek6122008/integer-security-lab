Lab Assignment-2

Aim: To convert values between data types (int to short, signed to unsigned, float to int, and string to numeric), observe the unsafe behaviour caused by truncation, sign conversion and overflow, and then implement safe conversion helpers that validate the value before converting and reject out-of-range inputs.

Tools Used:

  • Ubuntu/WSL
  • C language
  • GCC compiler
  • VS Code
  • Git and GitHub

Procedure:

a) Vulnerable Version (question1/unsafe.c)

Each value is assigned directly to the smaller or differently signed type with no checking. The value is printed before and after the conversion so the loss of information is visible.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int big = 70000;
    short s = big;
    printf("int %d -> short %d\n", big, s);

    int neg = -1;
    unsigned int u = neg;
    printf("signed %d -> unsigned %u\n", neg, u);

    float f = 3.9e9f;
    int i = f;
    printf("float %.1f -> int %d\n", f, i);

    const char *text = "99999999999999";
    int n = atoi(text);
    printf("string \"%s\" -> int %d\n", text, n);

    return 0;
}

b) Safe Version (question1/safe.c)

Every conversion goes through a helper that checks the value against the limits of the destination type first. If the value does not fit, the helper returns 0 and the program prints a clear error message instead of storing a wrong value. strtol replaces atoi because it reports both invalid text and out-of-range values.

#include <stdio.h>
#include <stdlib.h>
#include <limits.h>
#include <errno.h>
#include <math.h>

static int int_to_short(int v, short *out)
{
    if (v < SHRT_MIN || v > SHRT_MAX) return 0;
    *out = (short)v; return 1;
}

static int int_to_unsigned(int v, unsigned int *out)
{
    if (v < 0) return 0;
    *out = (unsigned int)v; return 1;
}

static int float_to_int(float f, int *out)
{
    if (isnan(f) || f < (float)INT_MIN || f > (float)INT_MAX) return 0;
    *out = (int)f; return 1;
}

static int string_to_int(const char *s, int *out)
{
    char *end; errno = 0;
    long v = strtol(s, &end, 10);
    if (end == s || *end != '\0') return 0;
    if (errno == ERANGE || v < INT_MIN || v > INT_MAX) return 0;
    *out = (int)v; return 1;
}
int main(void)
{
    int big = 70000; short s;
    if (int_to_short(big, &s)) printf("int %d -> short %d\n", big, s);
    else printf("Error: %d does not fit in a short\n", big);

    int neg = -1; unsigned int u;
    if (int_to_unsigned(neg, &u)) printf("signed %d -> unsigned %u\n", neg, u);
    else printf("Error: %d is negative, cannot convert to unsigned\n", neg);

    float f = 3.9e9f; int i;
    if (float_to_int(f, &i)) printf("float %.1f -> int %d\n", f, i);
    else printf("Error: float %.1f is outside int range\n", f);

    const char *text = "99999999999999"; int n;
    if (string_to_int(text, &n)) printf("string \"%s\" -> int %d\n", text, n);
    else printf("Error: string \"%s\" is not a valid int\n", text);

    return 0;
}

Results:

The unsafe program converted every value without checking and produced wrong results: 70000 was truncated to 4464 in a short, -1 became 4294967295 as an unsigned int, 3.9e9 was outside the range of int, and atoi silently returned a clamped value for a string too large for int. The safe program used range checks against SHRT_MIN/SHRT_MAX and INT_MIN/INT_MAX, and strtol with errno, so every out-of-range conversion was rejected with a clear error message instead of storing a corrupted value. This shows that in C a narrowing or sign-changing conversion never reports failure by itself, and validation must be written by the programmer.

No flags compiles silently and prints wrong values with no indication of a problem. -Wall -Wextra adds static analysis at compile time and reports the conversions that lose value where the compiler can see the constants, but it cannot see values computed at runtime. UBSan instruments the binary and reports the float-to-int conversion at runtime because it is undefined behaviour; it does not report the truncation or the sign conversion, since both are defined behaviour in C even though the result is not what the programmer wanted. ASan detects memory errors such as buffer overflow and use-after-free; this program has none, so it reports nothing, which shows ASan and UBSan cover different classes of defect and are not substitutes for each other.

Results:

The four configurations were compared and each was found to catch a different subset of defects. Warnings are cheap and catch mistakes before the program runs, sanitizers catch real runtime values but only for undefined behaviour, and defined-but-incorrect conversions such as truncation, sign change and a failed atoi are caught by none of them. Compiler hardening flags therefore reduce risk but do not replace the explicit range checks written in the safe version.
