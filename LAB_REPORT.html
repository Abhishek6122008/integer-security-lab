Lab Assignment-2

Aim: To convert values between data types (int to short, signed to unsigned, float to int, and string to numeric), observe the unsafe behaviour caused by truncation, sign conversion and overflow, and then implement safe conversion helpers that validate the value before converting and reject out-of-range inputs.

Tools Used:

  • Ubuntu/WSL
  • C language
  • GCC compiler
  • VS Code
  • Git and GitHub

Procedure:

a) Vulnerable Version (question1/unsafe.c)

Each value is assigned directly to the smaller or differently signed type with no checking. The value is printed before and after the conversion so the loss of information is visible. The sources are marked volatile so that the compiler cannot fold the conversions away at compile time, and the truncated short is then used as an index into a 10 byte heap buffer, which is the memory error used in Assignment-3.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // volatile stops gcc from folding these at compile time, so the
    // conversions really happen while the program runs
    volatile int big = 70000;
    short s = big;
    printf("int %d -> short %d
", big, s);

    volatile int neg = -1;
    unsigned int u = neg;
    printf("signed %d -> unsigned %u
", neg, u);

    volatile float f = 3.9e9f;
    int i = f;
    printf("float %.1f -> int %d
", f, i);

    const char *text = "99999999999999";
    int n = atoi(text);
    printf("string \"%s\" -> int %d
", text, n);

    // the truncated value from above is used as an array index,
    // 4464 % 100 = 64, still far outside a 10 byte buffer
    char *buf = malloc(10);
    buf[s % 100] = 'x';
    printf("wrote to buf[%d]
", s % 100);
    free(buf);

    return 0;
}

b) Safe Version (question1/safe.c)

The same four conversions are written again, but each one is guarded by an if statement that compares the value with the limits of the destination type taken from limits.h. If the value does not fit, the program prints a clear error message instead of storing a wrong value. atoi is replaced by strtol, which returns a long, so the string result can be range checked before it is put into an int.

#include <stdio.h>
#include <stdlib.h>
#include <limits.h>

int main(void)
{
    // before putting an int into a short we check it against the short
    // limits from limits.h, if it does not fit we refuse the conversion
    int big = 70000;
    if (big < SHRT_MIN || big > SHRT_MAX)
        printf("Error: %d does not fit in a short\n", big);
    else
        printf("int %d -> short %d\n", big, (short)big);

    // unsigned can only hold zero or positive values, so any negative
    // number is rejected instead of becoming a huge positive number
    int neg = -1;
    if (neg < 0)
        printf("Error: %d is negative, cannot make it unsigned\n", neg);
    else
        printf("signed %d -> unsigned %u\n", neg, (unsigned int)neg);

    // we compare the float with the int limits first, so we never do the
    // undefined conversion that the unsafe version does
    float f = 3.9e9f;
    if (f < (float)INT_MIN || f > (float)INT_MAX)
        printf("Error: float %.1f is outside int range\n", f);
    else
        printf("float %.1f -> int %d\n", f, (int)f);

    // strtol returns a long which is bigger than int, so we can check the
    // result first and only then cast it down, which atoi cannot do
    const char *text = "99999999999999";
    long v = strtol(text, NULL, 10);
    if (v < INT_MIN || v > INT_MAX)
        printf("Error: string \"%s\" is too big for an int\n", text);
    else
        printf("string \"%s\" -> int %d\n", text, (int)v);

    return 0;
}

Results:

The unsafe program converted every value without checking and produced wrong results: 70000 was truncated to 4464 in a short, -1 became 4294967295 as an unsigned int, 3.9e9 was outside the range of int, and atoi silently returned a clamped value for a string too large for int. The safe program used range checks against SHRT_MIN/SHRT_MAX and INT_MIN/INT_MAX, and strtol with errno, so every out-of-range conversion was rejected with a clear error message instead of storing a corrupted value. This shows that in C a narrowing or sign-changing conversion never reports failure by itself, and validation must be written by the programmer.

Two things had to be arranged before the flags had anything to report. The conversion sources are marked volatile so that gcc cannot fold them at compile time and skip instrumenting them, and the truncated short is used as an index into a 10 byte heap buffer so that there is a real memory error for ASan to find. No flags compiles silently and prints wrong values with no indication of a problem. -Wall -Wextra on their own report nothing here, because implicit conversions are legal C; -Wconversion is the flag that reports them, at compile time, before the program is ever run. UBSan instruments the binary and reports the float-to-int conversion at runtime because it is undefined behaviour; it does not report the truncation or the sign conversion, since both are defined behaviour in C even though the result is not what the programmer wanted. ASan reports the heap-buffer-overflow write with the line number of both the write and the malloc, but says nothing about any conversion. Signed-to-unsigned conversion and the failed atoi are caught by none of the four, because both are perfectly legal C, which is why the explicit range checks in the safe version are still necessary.

Results:

The four configurations were compared and each was found to catch a different subset of defects. Warnings are cheap and catch mistakes before the program runs, sanitizers catch real runtime values but only for undefined behaviour, and defined-but-incorrect conversions such as truncation, sign change and a failed atoi are caught by none of them. Compiler hardening flags therefore reduce risk but do not replace the explicit range checks written in the safe version.

Lab Assignment-4

Aim: To allocate a dynamic array with malloc, resize it with realloc and release it with free, printing the pointer value and the allocated size at every stage; to deliberately introduce an unchecked allocation return value (NULL pointer dereference) and a use-after-free through a dangling pointer, capture both with AddressSanitizer, and then write a corrected version that checks every return value, initialises the memory after allocating it, and sets the pointer to NULL after freeing it.

Tools Used:

  • Ubuntu/WSL
  • C language
  • GCC compiler with AddressSanitizer
  • VS Code
  • Git and GitHub

Procedure:

a) Vulnerable Version (question3/unsafe.c)

The program allocates space for 5 ints, prints the pointer and the size, grows the block to 10 ints with realloc and prints them again, then frees the block and prints the pointer a third time. The pointer normally changes at the realloc, because realloc is allowed to move the block, and the pointer printed after free is unchanged, which is exactly the problem: free changes the heap, not the variable. The two errors are selected by a command line argument so that each one can be captured separately, since ASan stops the program at the first error it finds.

#include <stdio.h>
#include <stdlib.h>

/* run with no argument : just the normal malloc -> realloc -> free trace
   run with 1           : error (a), unchecked malloc, NULL dereference
   run with 2           : error (b), use after free through a dangling pointer */
int main(int argc, char **argv)
{
    // stage 1, ask for 5 ints and print where they live and how big the block is
    size_t n = 5;
    int *a = malloc(n * sizeof(int));
    printf("malloc  : ptr = %p  size = %zu bytes\n", (void *)a, n * sizeof(int));
    for (size_t i = 0; i < n; i++)
        a[i] = (int)i * 10;

    // stage 2, grow the same array to 10 ints, realloc is allowed to move the
    // block, so the pointer printed here can be different from the one above
    n = 10;
    a = realloc(a, n * sizeof(int));
    printf("realloc : ptr = %p  size = %zu bytes\n", (void *)a, n * sizeof(int));

    // stage 3, hand the memory back, a keeps the old address and is now dangling
    free(a);
    printf("free    : ptr = %p  size = 0 bytes (block returned to the heap)\n", (void *)a);

    if (argc > 1 && argv[1][0] == '1') {
        // error (a) : this allocation is far too large so malloc returns NULL,
        // the return value is never checked, so the write goes through NULL
        int *big = malloc((size_t)-1);
        printf("huge malloc returned %p\n", (void *)big);
        big[0] = 1;
        printf("this line is never reached\n");
    }

    if (argc > 1 && argv[1][0] == '2') {
        // error (b) : the block was freed above but a still points at it,
        // so both of these touch memory the program no longer owns
        printf("dangling read  : a[0] = %d\n", a[0]);
        a[0] = 99;
        printf("dangling write : done\n");
    }

    return 0;
}

b) Corrected Version (question3/safe.c)

The same three stages are written again with the three rules applied. Every allocation is compared with NULL before it is used. The realloc result is stored in a temporary pointer first, so that if realloc fails the old block is still reachable and can be freed, instead of being leaked by overwriting the only pointer to it. The memory is initialised after each allocation, including the part that realloc added, which realloc leaves uninitialised. Finally the pointer is set to NULL immediately after free, so the dangling read of the unsafe version becomes impossible.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // every allocation is checked before it is used, so a NULL return
    // stops the program with a message instead of crashing on a write
    size_t n = 5;
    int *a = malloc(n * sizeof(int));
    if (a == NULL) {
        printf("Error: malloc of %zu bytes failed\n", n * sizeof(int));
        return 1;
    }
    printf("malloc  : ptr = %p  size = %zu bytes\n", (void *)a, n * sizeof(int));

    // fresh memory from malloc holds junk, so it is initialised before use
    for (size_t i = 0; i < n; i++)
        a[i] = (int)i * 10;

    // realloc result goes into a temporary first, if it fails the old block
    // is still valid and can be freed, assigning straight to a would lose it
    size_t m = 10;
    int *tmp = realloc(a, m * sizeof(int));
    if (tmp == NULL) {
        printf("Error: realloc to %zu bytes failed\n", m * sizeof(int));
        free(a);
        return 1;
    }
    a = tmp;
    printf("realloc : ptr = %p  size = %zu bytes\n", (void *)a, m * sizeof(int));

    // realloc does not initialise the part it added, so we do it here
    for (size_t i = n; i < m; i++)
        a[i] = 0;

    // free the block and immediately drop the address, a is no longer dangling
    free(a);
    a = NULL;
    printf("free    : ptr = %p  size = 0 bytes (pointer set to NULL)\n", (void *)a);

    // the same huge request as the unsafe version, but the result is checked
    int *big = malloc((size_t)-1);
    if (big == NULL)
        printf("Error: huge malloc failed, refusing to use the pointer\n");
    else
        free(big);

    // and the same use after free, but the NULL guard stops it
    if (a == NULL)
        printf("pointer is NULL after free, nothing to dereference\n");
    else
        printf("a[0] = %d\n", a[0]);

    return 0;
}

Explanation of each error and its security impact:

(a) Unchecked allocation return value. malloc((size_t)-1) can never be satisfied, so malloc returns NULL. The program does not check the return value and writes big[0] = 1, which dereferences a NULL pointer, and ASan reports SEGV on unknown address 0x000000000000. On a normal desktop this is a crash, which is already a denial of service in a server that is supposed to stay up. It is worse than a plain crash in general, because the fault address is the offset that was written: an expression like p[i] with a NULL p and a large attacker controlled i writes to a low but non-zero address, and on embedded targets, or anywhere the zero page can be mapped, that address is real memory, which turns the crash into a controlled write.

(b) Use after free through a dangling pointer. free returns the block to the heap but leaves the variable a holding the old address, so the following read and write touch memory the program no longer owns. ASan reports heap-use-after-free and prints three locations: the line of the bad access, the line where the block was freed, and the line where it was allocated. The security impact is larger than for the NULL dereference, because the freed block is immediately available to the next allocation. The stale write then lands inside whatever object now occupies that memory, which is the standard way to corrupt a length field, a flag, or a function pointer belonging to another part of the program, and the stale read leaks whatever the new owner has stored there. Use-after-free is one of the most commonly exploited defect classes in C for exactly this reason.

Results:

The pointer value and the allocated size were printed at each stage and showed that realloc can move the block to a new address while free leaves the variable pointing at the old one. Both deliberate errors were reproduced and captured by AddressSanitizer: the unchecked allocation produced a NULL pointer dereference, and the dangling pointer produced a heap-use-after-free with the allocation, free and access sites all identified. The corrected version applied the three rules, checking every return value, initialising after allocation, and setting the pointer to NULL after free, and ran to completion under ASan with no errors, which shows that dynamic memory in C is only safe when the programmer writes these checks, since the library reports failure through the return value alone and never by itself.
